## 3.1 本專題所採用的研究或開發方法及技術

本系統採前後端分離與模組化設計。系統分層包含展現層、業務邏輯層、資料持久層，以及獨立的影像辨識服務。

展現層為 iOS／Android App（`mobile-expo`，React Native），負責三角色畫面、推播註冊與 API 呼叫。業務邏輯層為 Node.js 搭配 Express 的本機後端（埠 5000），負責帳號、照護圈、SOS、待辦、血壓、訊息與推播。資料持久層為本機 MongoDB（資料庫名 `takecare`）。影像辨識服務為 `vision-runtime`（埠 8000），以 USB 外接攝影機取像，經 MediaPipe Pose 與自訓 TensorFlow Lite LSTM 進行跌倒判斷後，再回報後端。

如下圖：使用者透過 App 操作系統，App 以 JSON／REST 與 Node.js 後端交換資料，後端以 Mongoose 存取 MongoDB。跌倒辨識不在手機上執行，而是由本機影像服務分析後，再經後端寫入事件並以 FCM 通知看護與家屬。

（貼 `系統整體架構圖.png`）

在 Client-Server 通訊中，App 透過 `lib/api.js` 送出 HTTP 請求，與後端以 JSON 交換資料。需要登入的 API 以 JWT 識別身分。影像串流另由 App 連線影像服務的 `/stream`；連續回看畫面留在攝影機電腦，不上傳雲端。

## 3.2 工具和技術的選擇理由

### 3.2.1 React Native

本專題需要同時提供 iOS 與 Android，且須使用推播、麥克風、定位與安卓 Health Connect 等裝置功能，因此選擇 React Native 作為行動應用程式框架，而不是只做網頁，也不是只做 Kotlin 單平台。

### 3.2.2 Node.js 與 Express

後端使用 Node.js 搭配 Express，原因是適合建立 REST API，並與 App 同屬 JavaScript 生態。本系統包含登入、SOS、異常事件、待辦、血壓、照護圈與訊息等多個模組，路由集中於 `backend/index.js`，依 `/patient`、`/caregiver`、`/family`、`/vision` 等路徑管理。

### 3.2.3 MongoDB

本系統事件與警報欄位常隨需求調整（嚴重度、證據檔、結案狀態等），因此使用 MongoDB 文件資料庫，資料庫名稱為 `takecare`，部署於本機，不使用雲端 MySQL。帳號、照護圈、SOS、跌倒事件、待辦與血壓等 collection 由 Mongoose schema 建立。

### 3.2.4 JSON 與 JWT

App 與後端以 JSON 交換資料。登入成功後由後端簽發 JWT，後續請求以 Token 識別使用者與角色，避免每次操作重輸密碼，也避免三角色資料互相讀寫。

另提供 Google 登入與電子郵件驗證碼。測試時可使用既有帳號；正式註冊需設定 SMTP 才能寄出驗證信。

### 3.2.5 Firebase Cloud Messaging

SOS 與高嚴重度跌倒需要主動通知看護與家屬，且須同時支援 iOS 與 Android，因此採用 FCM，而不是 Android 本機 AlarmManager。看護結案方式為 SOS「已處理」、跌倒「已查看」；家屬對跌倒為知情、不處理。

### 3.2.6 MediaPipe Pose、LSTM 與 TensorFlow Lite

危險事件辨識需要從影像取得人體姿勢，並觀察一段時間的動作變化。本專題使用 MediaPipe Pose 從 RGB 影像估測 33 個關鍵點；再以自訓 LSTM 分析 30 幀姿勢序列；訓練完成後轉換為 TensorFlow Lite，於本機 `vision-runtime` 推論，不把連續畫面送到雲端視覺 API。

模型只輸出 fall 與 normal 兩類。蹲下、彎腰由自寫姿勢閘門與狀態機處理：每次記錄、不推播。確認摔倒且持續未起滿 5 秒，後端才建立高嚴重度警報並推播。

訓練資料包含 URFD、Le2i 與自錄誤報影片。接 App 的權重為 v8。影像來源為 USB 外接攝影機（OpenCV cam 0），不是 IP Camera。

## 3.3 處理流程

本系統主要處理流程包含會員登入、跌倒辨識、SOS 呼叫、監看回看及待辦指派。

### 3.3.1 會員登入流程

使用者開啟 App 後進行登入或註冊。輸入電子郵件及密碼後，App 以 HTTP POST 傳送至後端。

登入時呼叫：`POST /mobile/login`  
註冊時呼叫：`POST /mobile/register`

後端確認帳號及密碼（註冊另寄驗證碼）。驗證成功後產生 JWT，回傳 App。App 儲存登入資訊後進入對應角色主畫面（長輩、看護或家屬）。亦可使用 Google 登入。

流程：使用者輸入帳號密碼 → App 傳送登入資料 → Node.js 驗證 → 產生 JWT → App 儲存 Token → 進入主畫面。

### 3.3.2 跌倒辨識流程

影像服務以 USB 攝影機持續取幀，經 MediaPipe Pose 取得骨架後，以 30 幀視窗、每 5 幀呼叫 v8 TFLite。姿勢閘門區分站立、蹲下、彎腰與躺姿。蹲下與彎腰只寫低紀錄、不推播。確認摔倒後寫入後端異常事件，並保存事件短片。若 5 秒內站起，不建立高風險警報；未起滿 5 秒才推播看護與家屬。看護一鍵標記已查看。

（貼 `跌倒辨識流程圖.png`）

### 3.3.3 SOS 呼叫流程

長輩於 App 選擇呼叫內容（例如需要幫忙、跌倒、快來）後送出。約 10 秒內可取消。後端寫入 `sosevents`，並以 FCM 通知照護圈內看護與家屬。看護一鍵標記已處理。系統不自動撥打 119。

流程：長輩按呼叫 → POST `/patient/sos/trigger` → 寫入資料庫並推播 → 看護已處理。

### 3.3.4 監看與回看流程

看護與家屬可開啟監看。即時畫面連線影像服務 `GET /stream`。時間軸回看使用本機 JPEG 環，有檔的時段才上色，可跳秒播放。活動頁的事件短片走後端證據儲存，與 24 小時連續回看分開。

### 3.3.5 待辦流程

家屬新增重複待辦範本（`tasktemplates`）。當日展開為 `reminders`。看護可勾選完成並同步。待辦結案與跌倒結案分開，不混帳。

## 3.4 檔案關聯

本專案主要分為 `mobile-expo`、`backend` 與 `vision-runtime`。GitHub 專案為 `takecare-agent/MyApp`，現行分支 `vision-integration`。訓練資料與實驗圖在本機 `Fall_Detection_Lab`，不在此倉庫。

`mobile-expo` 負責使用者介面、推播註冊與 API 呼叫；`backend` 負責 API、業務邏輯與 MongoDB 存取；`vision-runtime` 負責取像、骨架、LSTM 推論與本機回看。

### 3.4.1 前端主要檔案

（1）`App.js`  
主控登入、驗證、分頁殼與功能頁切換，並處理 SOS 彈窗與推播進入。

（2）`AuthScreen.js`、`VerifyScreen.js`  
登入／註冊與電子郵件驗證碼。

（3）`MainTabShell.js`  
長輩、看護、家屬底部分頁整合。

（4）`NativeFeatureScreen.js`  
待辦、SOS、監看、照護圈等功能頁。

（5）`BloodPressureScreen.js`、`ChatScreen.js`、`VisionScreen.js`  
血壓、跨語訊息、監看即時與時間軸。

（6）`lib/api.js`  
向後端發送 REST 請求。

（7）`lib/pushNotifications.js`  
註冊 FCM token，接收 SOS／跌倒推播。

### 3.4.2 後端主要檔案

（1）`index.js`  
啟動 Express、定義 Mongoose schema、掛載全部路由。

（2）`googleAuth.js`、`lib/mobileAuth.js`  
Google／JWT 與 App 登入、驗證碼、權限。

（3）`lib/careCircle.js`  
照護圈成員（長輩與看護／家屬對應）。

（4）`lib/objectStore.js`  
事件截圖、短片與語音檔。

（5）`lib/whisperStt.js`  
語音轉文字（現行凍結）。

（6）`.env.example`  
環境設定範例。密碼與金鑰不提交 GitHub。

主要路由包含：`/mobile`、`/auth`、`/patient/*`、`/caregiver/*`、`/family/*`、`/vision/report`、Socket.IO `/chat`。

### 3.4.3 影像服務主要檔案

（1）`vision_api_server.py`：cam 0 取幀、MediaPipe、TFLite、狀態機、HTTP `/stream`。  
（2）`evidence_ring.py`：事件環與短片。  
（3）`playback_store.py`：監看回拉本機環。  
（4）`fall_detection_model_v8.tflite`：現行權重。

## 3.5 資料庫設計

本系統資料庫為本機 MongoDB 8，資料庫名 `takecare`。以 Mongoose 管理 collection，邏輯上以使用者為中心關聯 SOS、跌倒、待辦、血壓與訊息。實體關聯如下圖。

（貼 `資料表關聯圖.png`）

主要資料表功能與關聯說明見 `資料表_01.png`～`04.png`。

1. 使用者與照護圈：`users`、`carecirclemembers`  
2. 求救、異常與影像：`sosevents`、`abnormalevents`、`visiondetectionrecords`、`camerasessions`  
3. 待辦、提醒與日常照護：`tasktemplates`、`reminders`、`caredailyrecords`  
4. 生理量測與訊息：`bloodpressurerecords`、`chatmessages`、`customphrases`

`users` 以 email 為登入唯一帳號，密碼以 `passwordHash` 加密存放，`role` 區分受顧者、看護、家屬。照護圈以 `patientEmail` 與 `memberEmail` 對應。SOS 以 `patientUserId` 關聯使用者；看護已處理寫入 `handlerUserId`。跌倒事件以 `claimedByUserId` 記錄看護已查看。
